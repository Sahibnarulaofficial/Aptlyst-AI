6. **Explicit `__cause__` vs. `__context__` Semantics & Multi-Exception Chain Precedence:**
   - **Semantic Boundary:**
     - `__cause__` (`raise X from Y`) and DBAPI `.orig`: **explicit causal chaining** declaring `Y` as the underlying cause of `X`. (`raise X from None` sets `__cause__ = None` and `__suppress_context__ = True`, intentionally severing context.)
     - `__context__` (raising inside `except` / `finally` without `from`): **implicit ambient context** indicating an earlier active exception (e.g., logging bug inside `except IntegrityError:`, cleanup noise, or caught fallback). **An incidental `__context__` MUST NEVER override the classification of the actual active exception or an explicit causal chain.** Conversely, an incidental Tier-1 exception trapped inside `__cause__` or `__context__` underneath an outer exception MUST NEVER promote that outer exception into immediate `PROGRAMMING_ERROR` quarantine.
   - **Strict 5-Step Precedence in `classify_webhook_exception(exc, *, max_nodes=MAX_CHAIN_NODES_DEFAULT)`:**
     1. **Step 1 — Non-`Exception` `BaseException` Cancellation / Control Pass-Through:**
        `if not isinstance(exc, Exception): raise exc` — ensures `asyncio.CancelledError`, `KeyboardInterrupt`, and `SystemExit` propagate untouched (`ED-05`).
     2. **Step 2 — Authoritative `BillingWebhookError` Hierarchy (Outer Type Wins):**
        Check `isinstance(exc, ...)` on `exc` directly *before* Tier-1 or DB inspection:
        - `BillingWebhookLeaseError` -> `STALE_LEASE`
        - `BillingWebhookPermanentError` -> `PERMANENT_ERROR`
        - `BillingWebhookRetryableError` -> `RETRYABLE_ERROR`
        - Unspecialized bare `BillingWebhookError` -> `UNKNOWN_EXCEPTION` (`requires_alert=True`, preserving `exc.failure_category`) so accidentally instantiating the abstract base class never drops or silently suppresses alerting.
        - Optional `extract_db_error_details(exc)` populates `sqlstate`/`constraint_name`/`table_name` strictly as read-only diagnostic metadata without overriding the explicit webhook category.
     3. **Step 3 — Primary Active Tier-1 Exception Check (`isinstance(exc, UNEQUIVOCAL_PROGRAMMING_ERROR_TYPES)`):**
        Evaluates **top-level `exc` ONLY** (never walking `.orig`, `__cause__`, or `__context__`).
        - *Incidental DB context cannot mask a programming bug:* e.g., `TypeError` or `AttributeError` raised inside `except UniqueViolationError("23505"):` (`__context__` is retryable `23505`) still classifies immediately as `PROGRAMMING_ERROR`, NOT `RETRYABLE_ERROR`.
        - *Nested Tier-1 cannot hijack an outer wrapper/DB error:* e.g., `RuntimeError("wrap")` with `__context__ = TypeError`, `raise SdkError("timeout") from TypeError`, or `OperationalError("08006")` with `__context__ = AttributeError` does NOT hit Step 3, preventing accidental attempt-1 quarantine of wrapped library/DB failures.
     4. **Step 4 — Non-Override Guard Against Caught Implicit `__context__` on Non-DB Exceptions:**
        Before calling `classify_db_exception(exc)`, verify whether `exc` either (a) is itself a DB/driver/transport exception (has normalized `sqlstate`/`pgcode`/`diag`, SQLAlchemy/asyncpg DB attributes, or transport/disconnect type), OR (b) has an explicit causal child (`_safe_getattr(exc, "orig") is not None or _safe_getattr(exc, "__cause__") is not None`).
        - If `exc` is an ordinary non-DB Python exception (`KeyError`, `ValueError`, `RuntimeError`, Tier-2 exception including `NotImplementedError`) with **NO `.orig`, NO `__cause__`, and NO direct DB/transport attributes**, any DB error reachable *solely* via implicit `__context__` (e.g., `NotImplementedError` or `KeyError` raised after `except ForeignKeyViolationError("23503"):` or `except OperationalError("08006"):`) was an **already-caught ambient context** and **MUST NOT override** `exc` into `PERMANENT_ERROR` or silent `RETRYABLE_ERROR` (`requires_alert=False`). Such `exc` classifies cleanly as `UNKNOWN_EXCEPTION` (`requires_alert=True`).
